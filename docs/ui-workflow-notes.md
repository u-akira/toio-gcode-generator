# UI Workflow Notes

右側 UI を整理するときに参照するための、ユースケースと配置方針のメモです。

## 前提

現在よく使っている実行方式は `Motor timing` です。内部実装や保存値では `dead` / `DeadReckoning` という名前が残りますが、ユーザー向け表示では `Motor timing` を使います。

実行モードは描画や JSON 読み込みより前に決める必要があります。そのため、UI 上では描画パネルの先頭に置きます。

## 主な作業の流れ

1. 実行モードを選ぶ。
2. 絵を用意する。
3. シミュレーションする。
4. toio を準備する。
5. 実機で動かしてコマンドを調整する。
6. 調整後の JSON を export する。

## 絵を用意する

ユーザーは drawing area に直接線を描くことも、サンプルや JSON import から描画データを読み込むこともあります。

- drawing area で描いているときは `Undo` / `Redo` / `Clear` がすぐ必要になります。
- これらは右側パネルではなく、drawing area の近くに置く方が自然です。
- サンプルを使うときは drawing area をほぼ使いません。
- サンプル選択の代わりに JSON import を使うことがあります。
- JSON export は描画操作というより、調整後の保存操作です。

現在の方針:

- `Undo` / `Redo` / `Clear` は drawing area 左上に配置する。
- drawing area のヒントと描画失敗フィードバックは、`Undo` / `Redo` / `Clear` の横に表示する。
- `JSON Import` は描画データの入力手段として描画パネルに残す。
- `JSON Export` は調整後の保存として、toio コマンド確認エリア側に置く。

## 描画失敗フィードバック

補正できなかったときのログが右側ログだけに出ると、drawing area を見ているユーザーが気づきにくいです。

現在の方針:

- 描画失敗や短すぎる線のフィードバックは drawing area 近くに出す。
- 右側の `messageLog` にも詳細ログを残す。
- フィードバックは一時的に警告表示にし、一定時間後または次の描画開始時に通常ヒントへ戻す。

## シミュレーション

通常は toio を接続する前にシミュレーションします。ただし、toio の接続状態はすぐ確認できる必要があります。

- `Simulate` は描画または読み込みの後に押します。
- シミュレーション後は toio コマンドをよく確認します。
- シミュレーション失敗や補正ログは、右側ログだけでなく drawing area 近くにも一部表示した方がよいです。

整理方針:

- 実行モードは描画パネル先頭に置く。
- `Simulate` は実行セクションに置く。
- toio コマンド一覧はシミュレーション結果の確認場所として見やすく保つ。
- キャリブレーションとペン昇降は、シミュレーション結果を見た後に確認することがあるため、シミュレーションと実行の間へ置く。

## toio 準備

シミュレーションが終わってから toio を接続することが多いです。

- 接続状態は常に見える必要があります。
- 紙に置いたときにペンが付くか確認したいので、`Pen Up` -> `Pen Down` -> `Pen Up` をまとめて実行する 1 ボタンを使います。
- `Pen Up` / `Pen Down` 単独ボタンは通常 UI には置きません。

現在の方針:

- `Pen Check` ボタンを実行セクションに置く。
- `Pen Check` は `Pen Up` してから短く `Pen Down` し、最後に `Pen Up` へ戻す。
- `Pen Check` はペン用 toio が未接続のときは押せないようにする。

## ログ

実行ログは必要なときだけ確認できればよく、通常の実行操作と同じ面積で表示する必要はありません。

現在の方針:

- `messageLog` は実行セクションから外す。
- `ログ` として独立した折りたたみエリアに置く。
- デフォルトでは閉じておく。

## toio の調整

実機の動きを見ながら、toio コマンドの数値を入力して調整します。

- 入力方法は別途改善対象です。
- 調整後に JSON export します。
- コマンド調整と export は近くにある方が自然です。

現在の方針:

- `JSON Export` は toio コマンド確認エリア側に置く。
- コマンド数値入力の UI 改善は別タスクとして扱う。

## 詳細設定

次の領域は常用ではありません。

- 回転テストログ
- キャリブレーション
- ペン昇降

回転テストログは、toio の 90 度回転パラメータ調整のために使っていましたが、現在はほとんど使っていません。

キャリブレーションは基本的にほぼ見ませんが、toio を調整したときなどは確認します。ペン昇降も普段はほぼ気にしません。

今後の改善候補:

- キャリブレーション、ペン昇降、ログ、回転テストログはデフォルトで閉じた折りたたみ表示にする。
- 回転テストログは実行セクションから外し、デフォルトで閉じた折りたたみ表示にする。
- キャリブレーションとペン昇降は「詳細」グループへ寄せる。

## UI 整理の優先順位

1. drawing area 近くに `Undo` / `Redo` / `Clear` と描画フィードバックを置く。
2. 実行モードを描画パネルの先頭へ移す。
3. JSON import/export の意味を分ける。
4. toio コマンド確認と調整後 export を近づける。
5. `Pen Check` を実行前準備として使いやすくする。
6. キャリブレーション、ペン昇降、回転テストログを詳細グループへ畳む。
