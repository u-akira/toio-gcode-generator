# toio ペンプロッター UI / 制御仕様ドラフト

状態: MVP 仕様ドラフト
最終更新: 2026-07-14

## 目的

サンプルのような線画を描画できる Web UI を作り、その描画パスに合わせて 2 台の toio コア キューブを制御する。

- 1 台目: XY 移動を担当する移動用 toio
- 2 台目: ペンの上げ下げを担当するペン昇降用 toio
- Web UI 上で toio とペン先の動きをシミュレーションする
- Web UI から実機 toio を動かす
- 描画は原則として toio プレイマット上で行う
- ペンプロッター機構の詳細実測値は後でキャリブレーション値として反映する

## 確認済みの技術前提

- toio は Bluetooth Low Energy で通信する。
- toio の Primary Service UUID は `10B20100-5B3B-4571-9508-CF3EFCD7BBAE`。
- ID Information characteristic は `10B20101-5B3B-4571-9508-CF3EFCD7BBAE`。
- Motor Control characteristic は `10B20102-5B3B-4571-9508-CF3EFCD7BBAE`。
- Position ID から、キューブ中心の X/Y、角度、読み取りセンサー位置の X/Y、角度を取得できる。
- Position ID 座標は toio 独自の座標であり、ミリメートルそのものではない。
- toio の角度は 0-360 度で、X 軸方向が 0 度、時計回りが正。
- 目標指定付きモーター制御では、Position ID 座標と角度を指定して移動できる。
- 目標指定付きモーター制御の到達判定は、座標差 15 以内、角度差 4 度以内。
- TMD01SS は A3 サイズ 420 mm x 297 mm のシートとして扱う。
- toio コア キューブ単体付属の簡易プレイマットの Position ID 範囲は `(x=98,y=142)` から `(x=402,y=358)`。
- 画面背景には、この簡易プレイマットの画像を同じ Position ID 範囲へ合わせて表示する。
- ダイソー A3 クリアホルダー候補は、ポリプロピレン製、43 cm x 31 cm x 0.16 cm、3 個入り。
- ペン候補は、無印良品の「水性六角ミニカラーペンセット」10 色、商品番号 `18963027`。

## MVP 仕様

### 描画入力

最初の MVP はフリーハンド線画入力にする。

- SVG インポートや画像からの線画生成は初期版では扱わない。
- フリーハンド stroke を内部パスに変換する。
- 後から SVG や画像トレースを追加する場合も、同じパス変換パイプラインへ載せる。

### 描画範囲

初期対応の描画範囲は A3 簡易プレイマットとする。

- 実際の描画はプレイマット中心に合わせる。
- UI 上では Position ID 座標をそのまま描画空間として使い、実機 toio の位置表示とシミュレーション位置を一致させる。
- 初期版では A3 全面ではなく、中央 70-80% 程度の安全領域を描画可能範囲とする。
- UI にはフルマット境界と安全描画領域を両方表示する。
- ペン先パスはデフォルトで安全描画領域内に収める。
- ペンオフセット、toio 本体の干渉、クリアホルダー端、機構の可動範囲を検証した後で描画可能範囲を広げる。

### 描画面

紙ではなく、A3 クリアホルダー表面へ描画する。

- A3 簡易プレイマットを A3 クリアホルダーに挟む。
- toio はクリアホルダー越しにプレイマットの Position ID を読む。
- ペンはクリアホルダー表面に描画する。
- 描画後の線は消せる必要はない。
- クリアホルダーは交換可能な描画面として扱う。

早期に検証すること:

- toio がクリアホルダー越しに Position ID を安定して読めるか。
- ペンのインク、反射、傷、指紋が読み取りに影響しないか。
- 水性ペンがポリプロピレン表面に十分描けるか。
- ペン先摩擦で toio の移動が乱れないか。
- クリアホルダーとプレイマットが描画中にずれないか。

### ペン

初期ペン候補は無印良品の水性六角ミニカラーペンセットとする。

- toio サイズの機構に収まりやすい小型ペンとして扱う。
- 実装前または実機調整時に、軸径、長さ、キャップ、重心を実測する。
- 実測値はペン保持機構とペン先オフセットのキャリブレーションへ反映する。

## toio 機構と制御

### 全体構成

2 台の toio は物理的に連結されている。

- 移動用 toio はプロッター全体を XY 移動する。
- ペン昇降用 toio は XY 位置制御を行わず、ペン上げ下げ用のアクチュエータとして扱う。
- 実行側は、2 台目 toio の独立した XY 姿勢を追跡しない。

### ペン先と toio 中心の関係

ペン先は移動用 toio の中心とは一致しない。

- 実際の機構では、ペンは toio の後ろ側に取り付けられる。
- 描画パスは toio 中心の軌跡ではなく、ペン先の軌跡として扱う。
- toio の実効回転中心を、単純にキューブの幾何中心とは仮定しない。
- 技術資料と実測に基づき、回転中心オフセットをキャリブレーションする。

初期ジオメトリ設定:

```ts
type PlotterGeometry = {
  penOffsetFromReportedCenterX: number; // 前後方向。toio 前方がプラス、後ろがマイナス。
  penOffsetFromReportedCenterY: number; // 左右方向。後ろにペンがある機構では基本 0。
  rotationCenterOffsetX: number;
  rotationCenterOffsetY: number;
};
```

計画ルール:

- 描画パスはペン先座標で定義する。
- シミュレーションでは、ペン先パスと必要な toio 姿勢の両方を表示する。
- 実行時は、狙うペン先座標から toio の目標座標を逆算する。
- キャリブレーションでは、toio の報告位置とペン先位置の相対関係を測る。

### 向き

描画中は移動用 toio の向きを固定する。

- 固定向きは、後ろにあるペン先が描画領域の中心側に来る向きとする。
- 正確な角度値は、機構の向き、マットの置き方、toio の前後方向を合わせてキャリブレーションする。
- toio の向きを変える必要がある場合は、必ず先にペンを上げる。
- 回転中は描画しない。
- 回転完了後、必要ならペンを下げて描画を再開する。
- MVP では、できるだけ 1 枚の描画全体を同じ固定向きで処理する。

### ペン上げ下げ

ペン上げ下げは、ペン昇降用 toio の短時間モーター駆動で行う。

初期アクチュエータ設定:

```ts
type PenActuatorConfig = {
  upMotorSpeed: number;
  upDurationMs: number;
  downMotorSpeed: number;
  downDurationMs: number;
  settleMs: number;
};
```

実行ルール:

- `pen up` では、設定された短時間モーター駆動を送信し、`settleMs` 待つ。
- `pen down` でも同様に、設定された短時間モーター駆動を送信し、`settleMs` 待つ。
- 起動直後のペン状態は `unknown` とする。
- UI には手動の `pen up` / `pen down` ボタンを用意し、キャリブレーション時に使えるようにする。

### 速度

初期版では描画速度を一定にする。

- 描画移動は 1 つのキャリブレーション済み速度値を使う。
- 必要であれば、非描画移動だけ別の travel speed を持てるようにする。
- 線分ごとの速度調整は初期版では対象外。

### コマンド形式

シミュレーションと実機実行は同じコマンド列を消費する。

```ts
type PlotCommand =
  | { type: "move"; x: number; y: number; theta?: number; speed: number }
  | { type: "pen"; state: "up" | "down" }
  | { type: "rotate"; theta: number; speed: number }
  | { type: "wait"; ms: number };
```

## フリーハンドパス処理

フリーハンド stroke は、toio の移動計画に使う前に平滑化する。

初期パイプライン:

- raw pointer samples を取得する。
- 距離しきい値で軽く点を間引く。
- 手ブレを減らすために平滑化する。
- 平滑化後の stroke を移動セグメントへ変換する。
- drawing JSON には raw stroke と processed stroke の両方を保存する。

平滑化ルール:

- 意図的な角は残す。
- 急な方向変化を角として検出する。
- 検出した角をまたいで平滑化しない。
- 角と角の間の区間ごとに平滑化する。
- UI には smoothing strength を用意する。

## Web UI

### 実行環境

PC の Web Bluetooth 対応ブラウザを対象にする。

- 主な対象は PC の Chrome / Edge。
- モバイルブラウザと Safari は初期版では対象外。
- Web UI から 2 台の toio を個別に接続し、移動用とペン昇降用の役割を割り当てる。

### レイアウト

可能な限り 1 画面のワークベンチ UI にまとめる。

- メイン領域に描画キャンバスを置く。
- キャンバスには、マット境界、安全描画領域、描画パス、シミュレーションパス、toio 姿勢、ペン先位置を表示する。
- サイドパネルに、toio 接続、キャリブレーション、平滑化、速度、シミュレーション、実行操作をまとめる。
- 接続状態、ペン状態、シミュレーション有効性、緊急停止は常に見えるようにする。
- 初期版では、実行に必要な状態を別タブの奥へ隠さない。

### 必須操作

- フリーハンド描画
- undo / clear
- smoothing strength 調整
- safe area 表示
- シミュレーション実行
- 実機実行
- 緊急停止
- 2 台の toio 接続
- 手動 pen up / pen down
- キャリブレーション値編集
- 描画 JSON のエクスポート / インポート

## シミュレーションと安全要件

実機実行前のシミュレーションは必須とする。

- 実機実行ボタンは、最新の描画パスと最新のキャリブレーションでシミュレーションが成功している場合だけ有効にする。
- 描画、キャリブレーション、ジオメトリ、速度、ペン昇降設定を変更したら、前回のシミュレーション結果は無効化する。
- シミュレーションでは、安全描画領域、ペン先パス、必要な toio 姿勢、固定向き、pen-up 回転をチェックする。
- シミュレーション中と実機実行中の両方で緊急停止を使えるようにする。

初期精度目標:

- 最初のバージョンでは 5-10 mm 程度の描画ズレを許容する。
- 出力が意図した線画として認識できることを優先する。
- 細密プロッター精度より、信頼できる実行、キャリブレーション、シミュレーション、安全性を優先する。

将来の改善候補:

- ペンオフセットの高精度キャリブレーション
- 回転中心補正の改善
- 線分ごとの速度調整
- Position ID のライブ更新を使った閉ループ補正

## Dead reckoning 実行モード

Position ID 目標移動を使う既存モードとは別に、描画された図形を座標取得なしで描くための Dead reckoning モードを追加する。

このモードの目的:

- 描画された図形から、toio の左右モーター速度と駆動時間だけで描画するコマンド列を計算する。
- ペン先は toio から離れているため、線分間の回転や向き合わせではペン先オフセットを考慮する。
- toio の回転はモーター位置を中心とするため、単純にキューブ中心だけを回転中心とみなさない。
- 座標は実行中に取得しないため、回転の向きと量も左右モーター速度と時間から計算する。
- 計算結果はシミュレーション後に線分ごとに調整できるようにする。
- 実行時は、計算済みのモーターコマンドだけを順番に送信する。

### モード構成

実行モードは以下を持つ。

- `Position ID`: 既存の座標追従モード。Position ID 目標座標へ移動する。
- `Dead reckoning`: 線分長と向きから timed motor command を生成して実行する。

Dead reckoning は Position ID を一切使わない。ユーザーがペン先を図形の start 点に置き、toio 前方を最初の線分方向に合わせる。

### 座標系と入力

Dead reckoning では既存の描画座標をそのまま使い、線分長を mm 相当として扱う。

- 入力 JSON/SVG の 1 座標単位は、A3 サイズから大きく乖離していない限り `1mm` 相当として扱う。
- 既存の JSON/SVG サンプルは利用できる。
- Dead reckoning は読み込んだ図形の中央揃え、拡大縮小、用紙内フィットを行わない。
- Position ID モードと Dead reckoning モードで、描画データの表示位置は一致させる。
- 実行順、start、end は入力データの stroke 順と点順をそのまま採用する。自動最短経路化は初期版では行わない。

### 移動計画

Dead reckoning の移動計画は、描画 stroke を直線線分の列として扱う。

- 線分ごとに `pen up -> 回転 -> pen down -> 直進描画 -> pen up` を基本動作とする。
- 離れた stroke または離れた線分開始点へ移動する場合は、pen-up の travel 線分として `回転 -> 直進移動` を計画に含める。
- 回転中は必ず pen up とし、ペン先オフセットによる不要な弧を描かない。
- 曲線やフリーハンド stroke は、既存の平滑化と直線補正後の短い直線列として扱う。

### ペン先オフセットとシミュレーション

Dead reckoning シミュレーションは、toio とペン先を剛体として扱う理想モデルにする。

- 既存の `penOffsetX` / `penOffsetY` を Dead reckoning でも使う。
- `rotationCenterOffsetX` / `rotationCenterOffsetY` を反映し、回転時のペン先移動をシミュレーションできるようにする。
- シミュレーションは、理想モデルに線分ごとの調整値を反映したペン先位置、toio 本体位置、向きを start から end までアニメーション表示する。
- 床摩擦、滑り、加減速、電池残量による変化は初期版ではモデル化しない。実測誤差はキャリブレーションと線分ごとの調整で吸収する。

### Dead reckoning コマンド形式

Dead reckoning の実行コマンドは、Position ID 目標移動ではなく左右モーター個別速度と駆動時間へ変換する。

```ts
type DeadReckoningSegment = {
  id: string;
  kind: "draw" | "travel";
  start: { x: number; y: number };
  end: { x: number; y: number };
  lengthMm: number;
  heading: number;
  turnAngle: number;
  speed: number;
  durationScale: number;
  steeringTrim: number;
  turnDurationScale: number;
};

type TimedMotorStep =
  | { type: "pen"; state: "up" | "down" }
  | { type: "motor"; leftSpeed: number; rightSpeed: number; durationMs: number }
  | { type: "wait"; ms: number };
```

BLE 制御層には、左右モーターを個別指定できる `timedMotorPair(leftSpeed, rightSpeed, durationMs)` を追加する。

### 調整項目

Dead reckoning の調整は、全体設定と線分ごとの設定に分ける。

全体設定:

- `turnSpeed`: 回転時の基準モーター速度。
- `turnBalanceTrim`: 回転時の左右バランス補正。
- `drawSpeed`: 描画線分の既定速度。
- `travelSpeed`: pen-up travel 線分の既定速度。
- `mmPerSecAtDrawSpeed`: 基準描画速度における実測移動速度。初期値は理想値とし、実機キャリブレーションで更新する。
- `mmPerSecAtTravelSpeed`: 基準 travel 速度における実測移動速度。

線分ごとの調整:

- `speed`: その線分の直進モーター速度。
- `durationScale`: 線分長から計算した直進時間への倍率。
- `steeringTrim`: 直進時の左右モーター差補正。
- `turnDurationScale`: その線分直前の回転時間への倍率。

初期版では線分ごとの `enabled` は持たない。必要になった場合は詳細設定または次フェーズで追加する。

### 実行と停止

- Dead reckoning 実行前もシミュレーション必須とする。
- Dead reckoning では、実行前に「ペン先を start 点に置き、toio 前方を最初の線分方向に合わせる」確認を表示する。
- 実行中の主な安全停止は `Stop` ボタンとする。
- BLE 書き込み失敗または切断時は移動用 toio とペン昇降用 toio の停止を試み、実行を中断する。
- 座標を見ないため、実行中に用紙外へ出ることは検出しない。事前シミュレーションとユーザー確認で扱う。

### 初期版の対象外

- 線分ごとの `enabled`
- 自動最短経路化
- 摩擦、滑り、加減速の物理モデル
- 実行中の Position ID 補正
- 線分調整値の高度な保存、プロファイル管理

## 永続化

### キャリブレーション

初期版ではキャリブレーション値をブラウザの `localStorage` に保存する。

保存対象:

- マット / キャンバス変換
- 安全描画領域スケール
- 固定向き角度
- ペン先オフセット
- 回転中心オフセット
- ペン昇降モーター速度、駆動時間、待ち時間
- デフォルト描画速度

将来候補:

- キャリブレーション JSON のエクスポート / インポート
- 複数の名前付きキャリブレーションプロファイル
- 機構別、ペン別プリセット

### 描画データ

初期版では描画データを内部 JSON 形式でエクスポート / インポートできるようにする。

- フリーハンド stroke と変換済み path data を保存する。
- JSON を読み込むと描画を復元し、再度シミュレーションと実行ができる。
- SVG エクスポート / インポートは初期版では対象外。
- 外部ツールとの互換性より、内部パス処理を再現できることを優先する。

## MVP 実装方針

ブラウザベースのワークベンチとして実装する。

- フリーハンド線画を描ける。
- stroke を間引き、角を残して平滑化する。
- A3 簡易プレイマット中心基準の安全描画領域へ収める。
- ペン先パスを toio 目標座標へ変換する。
- ペン先、toio 姿勢、pen up/down をシミュレーションする。
- PC Web Bluetooth で 2 台の toio に接続する。
- 移動用 toio は固定向きで移動する。
- ペン昇降用 toio は短時間モーター駆動で pen up/down を行う。
- シミュレーション成功後だけ実機実行できる。

## 未決 / 実機検証事項

- クリアホルダー越しに Position ID を安定して読めるか。
- 水性ペンがクリアホルダーに十分描けるか。
- 実際のペン先オフセット値。
- 実効回転中心オフセット値。
- 固定向き角度。
- ペン昇降用 toio の `upMotorSpeed` / `upDurationMs` / `downMotorSpeed` / `downDurationMs` / `settleMs`。
